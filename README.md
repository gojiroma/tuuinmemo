# 通院メモ

心療内科の通院時に主治医へ見せるための、エントリ一覧・Markdownメモ・睡眠/歩数グラフを一体化した個人用記録アプリ。編集用と主治医閲覧用は別URLではなく、同じページ内のモード切替ボタンで行き来します。

## 構成

- `app.py` — Flask アプリ本体（`/` のページ配信 + `/api/*` の全エンドポイント。`/edit`は後方互換のため`/`へリダイレクト）
- `schema.sql` — Neon PostgreSQL 用スキーマ
- `templates/index.html` — フロントエンド一式（エントリ一覧・Markdownエディタ・グラフ）。デフォルトは主治医向けの読み取り専用表示で、ヘッダーの「編集モードに切替」ボタンを押すと編集フォームが現れる
- `static/theme.css` — デザイントークン・カード/ボタン/idle fade などの共通CSS
- `static/idle-ui.js` — 無操作が続くと副次的なUI（ナビリンクや期間トグルなど）を減光させる共通スクリプト
- `static/vitals-chart.js` — 睡眠・歩数グラフの日付バケット化とChart.js描画ロジック
- `static/markdown-editor.js` — Markdownエディタの箇条書き・見出し自動補完、Tabインデント、Alt+↑/↓行入れ替え
- `static/manifest.json` / `static/sw.js` / `static/icons/` — PWA（ホーム画面追加・簡易オフラインキャッシュ）。`sw.js`はスコープを`/`全体にするため`/sw.js`としても配信される
- `vercel.json` — 全リクエストを `app.py` に渡す設定（静的ファイル配信もFlask内部のstatic/templateで処理）
- `requirements.txt` — Python 依存パッケージ

## セットアップ

### 1. Neon で DB を用意

Neon でプロジェクトを作成し、接続文字列（`postgresql://...`）を取得します。

```bash
psql "$DATABASE_URL" -f schema.sql
```

### 2. ローカルで動作確認

```bash
pip install -r requirements.txt
export DATABASE_URL="postgresql://user:pass@host/db"
export ADMIN_TOKEN="任意の推測されにくい文字列"
python3 app.py   # http://127.0.0.1:5000
```

### 3. Vercel にデプロイ

```bash
vercel
```

Vercel プロジェクトの環境変数に `DATABASE_URL` と `ADMIN_TOKEN` を設定してください。

ルート`/`が唯一のページで、開くと常に閲覧モード（主治医向けの読み取り専用表示、かつ最新エントリを選択した状態）から始まります。ページ自体は認証なしで開けますが、アクセストークンを入力するまでメモ・バイタルなどのコンテンツは一切表示されません（`/api/*` 側でもトークンを検証するため、トークンなしにAPI経由で内容を取得することもできません）。入力したトークンは端末の`localStorage`に保存され、以後は自動的に送信されます。

トークンには2種類あります。
- **管理者トークン**（`ADMIN_TOKEN`環境変数の値）— 閲覧・編集の両方が可能。ヘッダーの「✏️ 編集モードに切替」ボタンを押すと、日付ジャンプ・削除ボタン・エディタ入力欄・CSVインポートなどの編集用UIが現れます（同じ2ペイン構成のまま）。もう一度ボタンを押すと閲覧モードに戻ります。管理者トークンでログイン中はヘッダーに「🔗 一時URL発行」ボタンが表示され、下記のゲスト用一時URLを発行できます。
- **ゲスト用一時URL**（管理者が発行）— 管理者トークンを教えずに、期限付きで閲覧のみを許可するための仕組みです。「🔗 一時URL発行」ダイアログで有効期限（1時間〜30日）を選んで発行すると `https://.../?guest=<トークン>` の形のURLが発行されます。これを開いた端末は自動的にそのトークンを`localStorage`に保存し（URLの`?guest=...`部分はアドレスバーから消去されます）、以後は常に閲覧モード固定（編集UI・一時URL発行ボタンは非表示）でアクセスできます。発行済みのURLは同ダイアログの一覧からいつでも「失効」でき、期限が切れたものも自動的に無効になります。

PWAとしてホーム画面に追加した場合の起動先も`/`です。

## API

全`/api/*`エンドポイントは`X-Access-Token`ヘッダー（`/api/vitals/import-csv`のような一部リクエストでは`?token=`クエリでも可）による認証が必須です。有効な管理者トークン／ゲスト用一時URLトークンのいずれとも一致しない場合は401、`ADMIN_TOKEN`環境変数自体が未設定の場合は503を返します。書き込み系（POST/PUT/DELETEおよびゲストURLの発行・一覧・失効）は管理者トークンのみ許可され、ゲスト用トークンで叩くと403になります。

| メソッド | パス | 内容 | 権限 |
|---|---|---|---|
| GET | `/api/auth/check` | トークンの検証用（成功時 `{"ok": true, "role": "admin"\|"guest"}`） | 管理者/ゲスト |
| GET | `/api/memo?date=YYYY-MM-DD` | 指定日のメモ取得 | 管理者/ゲスト |
| GET | `/api/memo?limit=200` | 直近N件のメモ一覧（エントリ一覧・キーワード検索用、デフォルト200件・最大5000件） | 管理者/ゲスト |
| POST | `/api/memo` | メモの作成/更新（日付でupsert。既存メモを10分以上ぶりに上書きする場合は直前の内容を`memo_history`へ保存） | 管理者のみ |
| GET | `/api/memo/<id>` | ID指定での取得 | 管理者/ゲスト |
| PUT / DELETE | `/api/memo/<id>` | ID指定での更新・削除 | 管理者のみ |
| GET | `/api/memo/<id>/history` | 編集履歴の一覧（新しい順、デフォルト50件・最大200件） | 管理者/ゲスト |
| GET | `/api/vitals?start=YYYY-MM-DD&end=YYYY-MM-DD` | 睡眠・歩数データ取得（省略時は直近50日） | 管理者/ゲスト |
| POST | `/api/vitals/import-csv` | CSVインポート（`type=sleep`\|`steps`, `file`） | 管理者のみ |
| GET | `/api/search-history?limit=20` | 直近使ったキーワード検索語（新しい順、デフォルト20件・最大100件） | 管理者/ゲスト |
| POST | `/api/search-history` | 検索語を履歴に保存（`{"query": "..."}`、同じ語なら日時だけ更新） | 管理者のみ |
| GET | `/api/guest-links` | 発行済み一時URLトークンの一覧 | 管理者のみ |
| POST | `/api/guest-links` | 一時URLトークンの発行（`{"hours": 24}`、1〜720時間） | 管理者のみ |
| DELETE | `/api/guest-links/<id>` | 一時URLトークンの失効 | 管理者のみ |

CSVは `date`/`day`/`timestamp` 列と `overall_score`(睡眠スコア)/`steps` 列を、大文字小文字を問わず部分一致で自動検出します（例: `timestamp` + `overall_score` / `Timestamp` + `Steps (steps)`）。睡眠データは `overall_score` 列が見つからない場合のみ、後方互換として `duration`/`sleep`(分) 列を旧仕様の睡眠時間として取り込みます。

バイタルグラフは「直近50日」「直近100日」「直近200日」「直近300日」「週次」「月次」を切り替えられます。週次・月次は範囲内の平均値（歩数は平均歩数/日、睡眠は平均睡眠スコア/日）を表示し、いずれも2025年12月を起点の固定範囲（ローリングウィンドウではなく全エントリをカバー）です。通院日を含む期間はオレンジ色でハイライトされ、凡例にも「通院日」のスウォッチが表示されます。「直近50日/100日」表示では通院日にカーソルを合わせると、グラフ内ではなくエントリ一覧・メモ表示エリア側にその日の記録が選択表示されます。エントリ一覧の行も、クリックだけでなくマウスホバーで即座に選択されます。「通院日」はエントリが存在する日を自動的にそう扱う仕様で、`is_clinic_day` は常に `true` を返します（別途チェックボックスでの指定はありません）。

## メモ

- Markdownの4セクション（生活変化・体調・今後の意向・質問相談依頼）はエディタの「4セクション挿入」ボタンで挿入されるテンプレートで、強制ではありません。
- Markdownエディタは「`- `で箇条書き継続」「`#`で見出し自動補完」「Tab/Shift+Tabでインデント」「Alt+↑/↓で行入れ替え」に対応しています（`static/markdown-editor.js`）。
- 本文中の `![alt](URL)` 形式の画像は「画像を結合保存」ボタンで縦に1枚のPNGへ結合してダウンロードできます。
- プレビュー内の画像はサムネイル程度（高さ220pxまで）に縮小表示され、マウスホバーで「🔍 クリックして拡大」と表示されます。クリックするとカルーセル形式のライトボックスで原寸大表示・前後の画像へ移動（矢印キー可）・ダウンロードができます。本文中で画像を空行を挟まず連続して並べる（`![a](url1)\n![b](url2)`）と横並びに、空行を挟むと縦並びになります。
- 一覧に出る1行サマリーは、本文の先頭行（見出し・箇条書きの記号は除く）をそのまま使います。別途サマリーを入力する欄はありません。
- 本文は入力停止後に自動保存されます（保存ボタンはありません）。オフライン時は `localStorage` に下書き保存し、オンライン復帰時に自動同期します。
- エントリの削除はエントリ一覧の各行にある🗑ボタンから行います。
- `/api/cleanup` のような自動削除機能は、実データ喪失リスクがあるため今回は未実装です。
- エントリ一覧の検索欄はキーワードを含む本文のエントリだけに絞り込みます（サーバー側のロード済み全エントリに対するクライアント側フィルタ）。検索語は`memo_search_history`テーブルに保存され、次回以降サジェスト（`<datalist>`）に表示されます。
- 「🕘 編集履歴」ボタンから、そのエントリを10分以上の間隔を空けて上書き保存した過去バージョンを一覧できます。各バージョンの「この内容を復元」で編集欄に読み込み、以後は通常の自動保存フローで保存されます（頻繁なオートセーブ自体は履歴を増やしません）。
